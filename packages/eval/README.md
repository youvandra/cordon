# @cordon/eval

G7 — the gate that is allowed to come out against the product.

```bash
npm test
```

## What it measures

A fence that refuses everything passes every other gate in this repository and
is useless. So this one asks the opposite question: **does the work still get
done?**

One task — a brief citing four paid sources, split across a root and its two
workers — run three times under Cordon and three times under a plain shared
cap, against acceptance criteria fixed before the first run. A brief counts as
done only when every source is cited with the body that seller actually served.
Both conditions are given the same authority: the window the owner signed.

## Two scenarios, and why the second one exists

**Nothing goes wrong.** Both conditions complete the same work for the same
money. What separates them is when the money leaves the owner: nothing at risk
before any work under Cordon, the whole window under a shared balance, because
a shared cap is released up front and enforced by a counter inside the process
doing the spending.

**One worker in a loop.** The shared cap has no way to say *and no single
worker may take all of it*, so the loop drains the window and the other
worker's sources are never bought. Under Cordon the loop is refused on its own
node and the sibling's half is still there.

## What it does not claim

The agents are **scripted and deterministic**, which is stated on the public
page rather than implied. A gate that measured a model's choices would be
measuring the model.

Latency is not measured: a local chain's confirmation time is not Arc's, and a
figure that cannot mean anything is not published.

It runs the same contracts on a local node, so it is evidence about the
contracts rather than about Arc. **G2** is the gate that is about Arc.

Its numbers are written into `packages/fixtures/src/eval.gen.ts` by the run
itself, and the verdict is computed from the criteria rather than written by
anyone.
